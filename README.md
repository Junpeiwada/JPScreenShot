# JPScreenShot

macOS のメニューバーから範囲キャプチャを行い、画像と同時に OCR でテキストを抽出して、**画像・テキストのどちらでもコピーできる**アプリ。

画面の文字は「焼き込まれたピクセル」なので、コピー不可の PDF や独自レンダラのアプリでは選択できない。macOS 標準のライブテキストやショートカット.app でも似たことはできるが、手数が多い（スクショ → サムネイルを開く → 選択 → コピー）か、テキストしか取れない。

このアプリは **1 回のキャプチャで画像とテキストの両方を得て、結果を見てからどちらを使うか選ぶ**。

## 使い方

| 操作 | 動作 |
|---|---|
| メニューバーアイコンを**クリック** | 範囲選択が始まる（メニューを開く手間を挟まない） |
| 結果ウィンドウが背面のときに**クリック** | 結果ウィンドウが前面に戻る。もう一度クリックすると範囲選択が始まる |
| ドラッグ | 範囲を選択してキャプチャ |
| `Esc` | 選択をキャンセル |
| アイコンを**右クリック** | メニュー（認識モード切替・環境設定・終了） |

キャプチャすると結果ウィンドウが開く。**画像は即座に表示され、テキストは OCR 完了後に埋まる**（OCR を待たされない）。

- **画像をコピー** / **テキストをコピー** / **保存**（PNG）
- テキストは**編集可能**。誤認識をその場で直してからコピーできる
- **等倍**チェックで、ピクセルそのままの表示とウィンドウに合わせた縮小を切り替え
- ウィンドウは自動で閉じない。閉じるのは「閉じる」ボタンか `Esc`

## 認識モード

用途に応じて 2 つ。結果ウィンドウ内で切り替えると**即座に再認識**され、選んだモードは次回の既定として記憶される。

| モード | 認識言語 | 言語補正 | 後処理 | 用途 |
|---|---|---|---|---|
| **日本語**（既定） | ja-JP, en-US | on | なし | 文章・UI テキスト |
| **コード** | en-US | off | 全角 → 半角 | ソースコード・パス・エラーメッセージ |

### 実測精度

| ケース | 結果 |
|---|---|
| 日本語の文章（28pt / 11pt） | **100%**（完全一致） |
| コード（コードモード） | **97.0%** |
| コード（日本語モードで撮った場合） | 69.7% |

コードモードは日本語を認識候補から外すことで、`l`（小文字 L）が `1` に化ける、`&&` が `88` になる、括弧が全角化する、といった誤りを防ぐ。**差は 27.3 ポイント**。

残る誤りは `O`（大文字オー）→ `0` のような字形の混同で、これは**意図的に自動補正していない**。文脈がないとどちらが正しいか判断できず、正しい文字を壊す危険があるため。結果ウィンドウで直す前提。

## 動作環境

- macOS 26 以降
- Apple Silicon / Intel（ユニバーサル）
- **画面収録の権限が必要**（初回のキャプチャ時に許可を求められる）

外部依存はない。OCR も Vision.framework によるオンデバイス処理で、**画像もテキストも外部に送信しない**。キャプチャ画像は「保存」を押したときだけディスクに書き込まれる。

## ビルド

`.xcodeproj` は生成物なので版管理していない。`project.yml` から生成する。

```sh
brew install xcodegen        # 未インストールなら
xcodegen generate
open JPScreenShot.xcodeproj
```

コマンドラインからビルドする場合:

```sh
xcodebuild -project JPScreenShot.xcodeproj -scheme JPScreenShot \
  -configuration Debug -derivedDataPath ./dd build
./dd/Build/Products/Debug/JPScreenShot.app/Contents/MacOS/JPScreenShot
```

### 開発時の注意

**画面収録の権限は署名の同一性に紐づく。** ad-hoc 署名だとビルドごとに `CDHash` が変わり、macOS が別アプリと見なして許可がリセットされる。そのため `project.yml` で開発用の署名 ID を固定している。

```yaml
CODE_SIGN_STYLE: Manual
CODE_SIGN_IDENTITY: "Apple Development"
DEVELOPMENT_TEAM: L897K2C26B      # 自分の Team ID に変える
```

「許可したのに撮れない」ときは、**実際に動いているバイナリのパスを確認する**。Xcode 既定の DerivedData に古いコピーが残っていて、そちらが起動していることがある。

```sh
pgrep -lf JPScreenShot
```

## 構成

```
Sources/
├── App/        アプリ本体・メニューバー常駐・全体制御・設定
├── Capture/    範囲選択オーバーレイ・ScreenCaptureKit・権限・座標変換
├── OCR/        Vision ラッパ・認識モード・全角半角の正規化
└── UI/         結果ウィンドウ・環境設定ウィンドウ
```

技術構成は SwiftUI（結果ウィンドウ）+ AppKit（`NSStatusItem`・オーバーレイ）、キャプチャは ScreenCaptureKit、OCR は Vision の `RecognizeTextRequest`（Swift 6 の厳格並行モードに適合する新 API）。

詳細は [Docs/要求仕様.md](Docs/要求仕様.md) と [Docs/実装計画.md](Docs/実装計画.md) を参照。実装中に踏んだ落とし穴（`sourceRect` の小数によるぼやけ、`NSWindow` の指定イニシャライザ、非 `Sendable` 型と `Task` など）は実装計画の 6 章に記録している。

## 第 1 版に含まないもの

- グローバルホットキー（キーボードだけで起動）
- 認識履歴の蓄積と検索
- ウィンドウ単位・全画面のキャプチャ（現状は範囲選択のみ）
- 縦書きの認識
- 保存形式の選択（現状 PNG 固定）
