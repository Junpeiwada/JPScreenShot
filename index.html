JPScreenShot

メニューバーから範囲キャプチャ。画像とテキストを同時に取得して、 結果を見てからどちらを使うか選べる macOS アプリ。

最新版をダウンロード

macOS 26 以降 / Apple Silicon・Intel 対応 / Developer ID 署名・公証済み

何が違うのか

画面の文字は「焼き込まれたピクセル」なので、コピー不可の PDF や独自レンダラのアプリでは選択できない。 macOS 標準のライブテキストやショートカット.app でも似たことはできるが、手数が多い （スクショ → サムネイルを開く → 選択 → コピー）か、テキストしか取れない。

JPScreenShot は 1 回のキャプチャで画像とテキストの両方を得る。 画像は即座に表示され、テキストは OCR が終わり次第埋まるので、OCR を待たされない。

使い方

操作動作
メニューバーアイコンをクリック範囲選択が始まる（メニューを開く手間がない）
ドラッグ範囲を選択してキャプチャ
Esc選択をキャンセル
アイコンを右クリックメニュー（認識モード切替・環境設定・終了）
  • 画像をコピー / テキストをコピー / 保存（PNG）
  • テキストは編集可能。誤認識をその場で直してからコピーできる
  • 等倍チェックで、ピクセルそのままの表示と縮小表示を切り替え
  • ウィンドウは自動で閉じない

認識モード

用途に応じて 2 つ。結果ウィンドウ内で切り替えると即座に再認識され、選んだモードは次回の既定として記憶される。

モード認識言語言語補正後処理用途
日本語（既定）ja-JP, en-USonなし文章・UI テキスト
コードen-USoff全角 → 半角ソースコード・パス・エラー

実測精度

ケース結果
日本語の文章（28pt / 11pt）100%（完全一致）
コード（コードモード）97.0%
コード（日本語モードで撮った場合）69.7%

コードモードは日本語を認識候補から外すことで、l が 1 に化ける、 && が 88 になる、括弧が全角化する、といった誤りを防ぐ。差は 27.3 ポイント。

残る誤りは O（大文字オー）→ 0 のような字形の混同で、これは意図的に自動補正していない。 文脈がないとどちらが正しいか判断できず、正しい文字を壊す危険があるため。結果ウィンドウで直す前提。

プライバシー

外部依存はない。OCR も Vision.framework によるオンデバイス処理で、 画像もテキストも外部に送信しない。 キャプチャ画像は「保存」を押したときだけディスクに書き込まれる。

初回のキャプチャ時に画面収録の権限を求められる。これは macOS が画面の内容を読むアプリに要求するもので、 システム設定 → プライバシーとセキュリティ → 画面収録 から確認・変更できる。

自動更新

Sparkle による自動更新に対応している。新しい版が出るとアプリが知らせ、 メニューの「更新を確認…」からいつでも手動確認できる。 更新の配信物は EdDSA 署名で検証される。
