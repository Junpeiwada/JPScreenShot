## 1. 背景と目的

画面に表示されている文字は「焼き込まれたピクセル」であり、コピー不可の PDF や独自レンダラのアプリでは選択・コピーができない。macOS 標準のライブテキストやショートカット.app でも同等のことは可能だが、

- ライブテキストは「スクショ→サムネイルを開く→選択→コピー」と手数が多い
- ショートカット.app はテキストのみで、**画像とテキストのどちらを取るか後から選べない**

本アプリは **1 回のキャプチャで画像とテキストの両方を得て、その場でどちらを使うか選ぶ**ことを目的とする。キャプチャ結果を見て判断できることが、既存手段に対する優位点である。

## 2. スコープ

### 第 1 版に含む

- メニューバーからの起動と範囲選択キャプチャ
- クリックによるウィンドウ単位のキャプチャ（影の有無は設定で選べる）
- キャプチャ画像のプレビュー表示
- OCR によるテキスト抽出と表示
- 画像のコピー / テキストのコピー / 画像のデスクトップ保存

### 第 1 版に含まない

[11. 対象外・将来課題](#11-対象外将来課題) を参照。

## 4. 画面・UI 要求

### 4.1 メニューバー

- アプリは **Dock に出さず**メニューバーのみに常駐する（`LSUIElement`）
- メニューバーアイコンを**クリックすると即座に範囲選択モードへ入る**
  - 「メニューを開いて項目を選ぶ」の 1 手間を挟まない。クリック＝キャプチャ開始とする
- **右クリック（または長押し）でメニュー**を表示し、以下を提供する
  - 範囲を選択してキャプチャ
  - 認識モードの切り替え（[6.3](#63-認識モードの設計) 参照）
  - 設定…（⌘,）
  - JPScreenShot について
  - 終了
- 終了（⌘Q・メニューの「終了」）の前に**本当に終了するか確認する**。押し間違いで常駐が消え、気づかないままキャプチャできなくなるのを防ぐ
  - 確認するのはユーザーの終了操作だけとする。自動更新（Sparkle）による再起動やログアウト・再起動に伴う終了は止めない

### 4.2 範囲選択モード（レティクル）

- 全スクリーンを暗いオーバーレイで覆い、カーソルを**十字（レティクル）**に変更する
- ドラッグで矩形範囲を選択する。選択中は以下を表示する
  - 選択範囲の内側は**暗転を解除**して元の画面を見せる
  - 選択範囲の**寸法（幅 × 高さ px）**をカーソル近傍に表示する
- **マルチディスプレイに対応**する。すべてのスクリーンにオーバーレイを出し、どの画面でも選択できる
- **クリック（ドラッグなし）でそのウィンドウをキャプチャ**する（[CAP-06](#51-キャプチャ)）
  - ドラッグ開始前は、カーソル下のウィンドウを**淡くハイライト**して「クリックすれば撮れる」ことを示す
  - **見えていないウィンドウは対象にしない。** 他のウィンドウに覆われて事実上見えていないものはハイライトもキャプチャもしない（画面上で見えているものだけを選べる）。フルスクリーンのアプリが出ている画面では、そのアプリしか選べない
  - ハイライトは**実際に見えている領域の形**で描く。ウィンドウ全体の矩形を塗ると、手前のウィンドウに隠れている部分まで色が乗り、見えている重なりと食い違う
  - ハイライトには**アプリ名とウィンドウタイトル**を重ねる。同じ位置・同じ大きさのウィンドウが重なっていると、形だけではどれが撮れるのか分からない
  - ハイライトは選択枠（白の実線）と見た目を変える（アクセントカラーの塗り＋破線）。確定した選択と、これから起きうる候補を区別する
  - ドラッグが始まったらハイライトは消す。両方出したままではどちらが撮れるか分からない
- キャンセル操作
  - `Esc` キーでキャンセルし、何もせず終了する
  - ~~ドラッグせずにクリックしただけの場合もキャンセルとする（誤クリック対策）~~ → **クリックはウィンドウキャプチャに割り当てた**（下記注記を参照）
  - クリックした位置に対象ウィンドウがない場合（デスクトップ・壁紙など）はキャンセルとする
- 選択範囲が極端に小さい場合（例: 8px 未満）は無効としてキャンセル扱いにする
  - わずかに動いた場合をウィンドウキャプチャに転用はしない。「ウィンドウを撮ろうとして手が震えた」とも「小さすぎる範囲を選んだ」とも解釈できるため、意図しないウィンドウを撮るより何もしない方が害が小さい

> **クリック操作の割り当てを変更した理由**
>
> 当初はドラッグなしクリックを誤クリック対策のキャンセルにしていたが、ウィンドウ単位のキャプチャ（当初は[将来課題](#11-対象外将来課題)）を追加するにあたり、macOS 標準のスクリーンショット（Space キーでウィンドウモード）に近い直感を優先してクリックに割り当てた。
>
> 誤クリックの逃げ道は残っている。デスクトップなど対象ウィンドウがない場所のクリックは従来どおりキャンセルになり、`Esc` も引き続き使える。

### 4.3 結果ウィンドウ

キャプチャ完了後、結果ウィンドウを表示する。レイアウトは**上に画像、下に OCR テキスト**の縦積みとする（ユーザー要求どおり）。

```
┌─────────────────────────────────────┐
│ ┌──┐ ┌───────────────────────────┐ │
│ │選│ │                           │ │
│ │矢│ │  [ キャプチャ画像 ]         │ │
│ │線│ │  （注釈を描き込める）        │ │
│ │四│ │                           │ │
│ │円│ └───────────────────────────┘ │
│ │字│                               │
│ │ぼ│                               │
│ │モ│                               │
│ │色│                               │
│ │太│                               │
│ └──┘                               │
├─────────────────────────────────────┤
│  [テキストを認識] [認識モード]          │
│  ↓ 押すと OCR 結果の欄が開く            │
│  OCR 結果（テキスト、編集可）           │
├─────────────────────────────────────┤
│ [新規キャプチャ] [画像をコピー]         │
│ [テキストをコピー] [保存]               │
│          [取り消し][やり直し][等倍][閉じる]│
└─────────────────────────────────────┘
```

左端の縦並びは**注釈のツールレール**（上から 選択・矢印・線・四角・円・テキスト・ぼかし・モザイク、その下に色と太さ）。画像欄は注釈を描き込めるキャンバスで、詳細は [4.4](#44-注釈編集キャンバスとツールレール)・[5.5](#55-注釈編集) を参照。

要求事項:

- 画像は**アスペクト比を保って**プレビュー領域に収める。等倍より大きく拡大はしない（注釈の座標・線の太さ・文字の大きさも一緒に縮む）
- OCR テキストは**選択可能かつ編集可能**とする。誤認識をその場で直してからコピーできることを重視する（[6.2](#62-誤認識の傾向) のとおり記号やコードは誤認識が残るため）
- **OCR は「テキストを認識」を押すまで実行しない**（OCR-01）。押すまではテキスト欄を 1 行のバー（ボタンと認識モード）に縮め、画像に場所を譲る。押すとテキスト欄が開き、画面に余裕があればその分ウィンドウを伸ばす。「テキストをコピー」は OCR を始めるまで出さない
- 「新規キャプチャ」で結果ウィンドウから続けて撮れる（CAP-09）
- OCR が 1 文字も取れなかった場合は、テキスト欄に「テキストを認識できませんでした」と表示し、テキストコピーボタンは無効化する
- OCR 処理中は**プレースホルダまたはスピナー**を表示する。画像プレビューは OCR 完了を待たず先に表示する
- ウィンドウはリサイズ可能とし、画像とテキストの領域比を**ドラッグで変更できる**ことが望ましい
- `Esc` で閉じられる（ただし注釈の操作中は段階的に使う。ANN-12）。コピー実行後に閉じるかは設定（下記 5.3 参照）

### 4.4 注釈編集（キャンバスとツールレール）

結果ウィンドウの画像欄に、矢印・線・四角・円・テキスト（袋文字）・ぼかし・モザイクを**ベクトルのオブジェクト**として描き込める。描いた後もクリックで選び直して移動・変形・スタイル変更ができる。画面構成は Skitch 風（左に縦のツールレール、詳しい設定は選択したオブジェクトの近くのポップオーバー）。検討経緯と決定事項は [注釈編集_画面構成案.md](注釈編集_画面構成案.md)、実装の段取りは [実装計画-注釈編集.md](実装計画-注釈編集.md)。

**ツールレール（左端）**

- ツールのツールチップは「矢印（A）」の形でキーを併記する。上から 選択（`V`）・矢印（`A`）・線（`L`）・四角（`R`）・円（`O`）・テキスト（`T`）・ぼかし（`B`）・モザイク（`M`）。既定は選択ツールで、撮ってすぐコピーする従来の使い方は変わらない
- その下に**色**（今の色を表す丸ボタン 1 つ。押すとポップアップで**プリセット 6 色（3 列 × 2 行）と「その他の色…」（カラーパネル）**から選ぶ。プリセットを選ぶとポップアップは閉じる）と**太さ**（細 3pt・中 5pt・太 9pt）。選択中のオブジェクトがあればそれに、なければ**次に描くもの**に効く
- 取り消し／やり直しはボタンバーに置く（レールが縦に長くなりすぎるため）

**ポップオーバー（詳しい設定）**

- **クリックで選択したとき（ドラッグなし・選択が 1 件以上）に自動で開く**。Shift クリックの追加選択でも開く。**移動や変形をし終えてマウスを離したときも開く**（未選択のものをいきなりドラッグした場合も。ドラッグ中は閉じておく）。描き終えた直後・範囲選択の直後・矢印キーでの移動・テキスト編集の開始では開かない（続けて描く・キーで動かす流れを邪魔しない）。`⌘I` や右クリックメニューの「スタイル…」でも開ける。ダブルクリックはテキスト編集に使うので割り当てない
- 開いている間も、キャンバスのクリック・ドラッグ・キー操作（⌫・矢印・`Esc`・ツールキー）はそのまま効く。選択が変われば中身と位置を更新し、選択を解除すると閉じる
- オブジェクトの上側に出し、入らなければ下側。ドラッグを始めたら閉じる
- 中身は種類で変わる
  - 図形: 種類の切り替え（矢印⇔線⇔四角⇔円）・色・太さ・先端（矢印のみ）・線種・塗り（四角・円のみ）・影
  - テキスト: 見本・フォント・ウエイト・サイズ・文字色、折りたたみ「縁取りと影」（縁取りの有無・色・太さ、影。開閉は記憶する）
  - 数値の項目（太さ・サイズ・強さなど）はスライダーに加え、数値欄とステッパーで正確な値を入れられる
  - ぼかし／モザイク: 種類の切り替え・強さ・形（四角／楕円）
- 複数選択中は共通項目（色・太さ・影）だけを出す

**操作**

| 操作 | 結果 |
|---|---|
| オブジェクト（描画ツールでは線上・面の枠の帯）をクリック | 選択（ハンドル表示）。`Shift` クリックで追加・解除。ドラッグなら選択してそのまま移動 |
| 描画ツールで何もない所・面の内部をドラッグ | 新しく描く。描き終えたらそれを選択し、ツールは維持（3pt 未満のドラッグでは作らない）。`Shift` で正方形・正円・45° 刻み |
| 選択ツールで空白をドラッグ | 範囲で複数選択 |
| 選択中のオブジェクトをドラッグ | 移動 |
| 選択中のオブジェクトの**選択枠（破線）の辺の近く（画面上 6pt 以内）**、または線・矢印・塗りなしの四角/円の線の上をドラッグ | **ツールによらず移動**（複数選択ならまとめて）。ハンドルは変形が優先。線・矢印にも破線の選択枠を出す。**描画ツール中は、面（ぼかし・モザイク・テキスト・塗りありの四角/円）の内部では移動にならず新規作成**（枠の辺の帯だけが移動）。選択ツールでは本体のどこでも移動。選択中より手前にある未選択のオブジェクトをクリックしたら、そちらを選ぶ。テキストツールでは、動かさずに離せば編集（選択中の図形なら新規テキスト）、ドラッグすれば移動 |
| 右クリック（`Control` クリック） | オブジェクトの上なら（未選択ならまず選択して）コンテキストメニュー: スタイル…（`⌘I`）・複製（`⌘D`）・前面へ・背面へ・削除（`⌫`）。何もない所では出さない |
| ハンドルをドラッグ | 変形（矩形は 8 点、矢印・線は両端。複数選択中は変形しない。テキストは拡縮で文字サイズが変わる） |
| テキストツールでクリック | その位置に入力欄を重ねて入力開始。外をクリック・`Esc`・`⌘Return` で確定（空なら作らない） |
| テキストをダブルクリック | 文字の編集を再開 |

**カーソルと押したときの動き**

| 場所 | カーソル | 押したときの動き |
|---|---|---|
| ハンドル | 各ハンドルの変形カーソル | ドラッグで変形 |
| 選択中のオブジェクトの本体、または選択枠（破線）の辺の帯（6pt） | 開いた手（ドラッグ中は握った手） | ドラッグで移動（ツールによらない）。離すと小窓を自動表示 |
| 未選択のオブジェクト（選択ツール: 本体のどこでも／描画ツール: 線・矢印・塗りなしの四角/円の線上、面は外接枠の辺の帯） | 指差し | クリックで選択（小窓を自動表示）、ドラッグなら選択してそのまま移動 |
| 描画ツールで、何もない所・面（ぼかし・モザイク・塗りありの四角/円）の内部 | 十字に小さな「+」 | ドラッグで新規作成。クリックだけなら選択解除 |
| テキストツール | I ビーム | クリックで入力開始（既存テキストなら編集） |
| 選択ツールで何もない所 | 矢印 | ドラッグで範囲選択、クリックで選択解除 |

描画ツールでは**見た目に合わせ、不透明な面（塗りつぶしの四角/円・ぼかし・モザイク）の内部では、その奥にあるものを選ばない・動かさない**（押せば新規作成。枠の帯だけが対象）。テキストと半透明の塗りは後ろが見えるので遮らない。楕円形の面の帯は楕円の輪郭からの距離で判定する。`Shift` 押下中は、選択中のものの上のカーソルが指差しになり、押すと選択の追加／解除になる。

優先順は、ハンドル → 選択中より手前の未選択のオブジェクト → 選択中の本体 → 選択枠の辺の帯 → 最前面のオブジェクト。カーソルと押したときの動きは同じ判定（`AnnotationInteraction.pressAction`）から決めるので、表示と動作はずれない。修飾キーではカーソルは変わらない。

**キーボード**（キャンバスにフォーカスがあるときだけ。OCR テキスト欄・テキスト入力中は効かない）

| キー | 動作 |
|---|---|
| `V` `A` `L` `R` `O` `T` `B` `M` | ツール切り替え（修飾キーなし） |
| `⌫` | 選択中を削除 |
| `⌘Z` / `⇧⌘Z` | 取り消し／やり直し。メインメニュー経由で First Responder に届くため、キャンバスと OCR テキスト欄で対象が自然に分かれる |
| `⌘D` | 複製（10pt ずらして複製側を選択）。メニュー「編集 > 複製」 |
| 矢印キー（`⇧` で 10pt） | 選択中を 1pt ずつ移動。キーを押し続けた一連は取り消し 1 回にまとまる |
| `Esc` | テキスト編集中なら確定 → 選択があれば選択解除 → 何も無ければウィンドウを閉じる。OCR テキスト欄にフォーカスがあるときは従来どおり閉じる |

**重なり順**は下から 元画像 → ぼかし・モザイク → 図形・テキスト で固定。ぼかしの上に矢印を置いても矢印はぼけない。

> ウィンドウを閉じると注釈は破棄される（[11](#11-対象外将来課題)）。**新規キャプチャで結果ウィンドウが新しい結果に置き換わるときも、前のウィンドウの注釈は確認なしに破棄される**（コピー・保存していない注釈は戻せない。結果を残したいときは、新規キャプチャの前にコピー・保存する）。

## 5. 機能要求

### 5.1 キャプチャ

| ID | 要求 |
|---|---|
| CAP-01 | メニューバーアイコンのクリックで選択モードに入る（範囲選択とウィンドウ選択を兼ねる）。例外は CAP-08 |
| CAP-02 | ドラッグで指定した矩形範囲を、**Retina 解像度のまま**（ダウンスケールせず）キャプチャする |
| CAP-03 | マルチディスプレイ環境でも、選択した画面の内容を正しく取得する |
| CAP-04 | オーバーレイ自身がキャプチャに写り込まないこと |
| CAP-05 | `Esc` でキャンセルできる。クリック位置に対象ウィンドウがない場合もキャンセルとする |
| CAP-06 | **クリック（ドラッグなし）でそのウィンドウ 1 つをキャプチャ**する。ドラッグ開始前はカーソル下のウィンドウをハイライトする。**画面上で見えているウィンドウのみを対象**とし、他のウィンドウに覆われて見えていないものは選べない（フルスクリーンのアプリがある画面では、そのアプリしか選べない）。ハイライトは**実際に見えている領域の形**で描き、隠れている部分は塗らない。あわせて**アプリ名とウィンドウタイトル**を重ねて表示する（同じ位置・同じ大きさのウィンドウが重なっていると形だけでは判別できないため） |
| CAP-07 | ウィンドウキャプチャに**ドロップシャドウを付けるかを設定で選べる**。既定は付ける。影を付けても**ウィンドウ本体の解像度は劣化させない**（CAP-02 と両立させる） |
| CAP-08 | **結果ウィンドウを見失っているときに限り、アイコンのクリックはキャプチャではなく結果ウィンドウの呼び戻しを行う**（CAP-01 の例外）。もう一度クリックすればキャプチャが始まる。右クリックメニューの「範囲を選択してキャプチャ」は明示的な指示なので、この例外を適用せず常にキャプチャを始める |
| CAP-09 | **結果ウィンドウの「新規キャプチャ」（⌘N）で選択モードに入る。** 選択中は結果ウィンドウを隠し（撮りたい場所を覆わないため）、撮影に成功したら新しい結果に置き換える。`Esc` 等でキャンセルした場合やキャプチャに失敗した場合は、元の結果ウィンドウを戻す |

実装方針: **ScreenCaptureKit** を用いる。`CGWindowListCreateImage` は非推奨化が進んでいるため新規採用しない。

CAP-08 の「見失っている」の判定は次のとおり（`ResultWindow.shouldBringToFront`）。撮った結果を見ながら他アプリを操作したあと、アイコンを押した瞬間に次のキャプチャが始まって結果ウィンドウを見失うのを防ぐのが目的なので、**見えているなら前面化しない**を原則とする。

- **最小化されている** → 呼び戻す（Dock の中で完全に見えておらず、戻しても撮影対象を隠さない）
- **他アプリが前面**（`NSApp.isActive == false`）→ 呼び戻す
- 自アプリがアクティブ → 呼び戻さない。アクティブな間はウィンドウが `.floating` で手前にいるため見失っていない。設定など**同じアプリの別ウィンドウがキーでも見えている**ので `isKeyWindow` では判定しない
- **別 Space にある** → 呼び戻さない（`NSApp.activate` すると Space ごと切り替わり、いま撮ろうとしている画面から引き剥がしてしまう）
- **⌘H で隠されている** → 呼び戻さない（隠したのはユーザーの意思）

この判定は「`NSStatusBarButton` のクリックでは `NSApp` がアクティブにならない」ことに依存する。崩れると「何度クリックしてもキャプチャが始まらない」詰み方をする。呼び戻し自体はステータスメニューの「結果ウィンドウを表示」と同じ `ResultWindow.bringToFront()` を使う（あちらは明示的な指示なので無条件に呼び戻す）。

ウィンドウキャプチャ（CAP-06 / CAP-07）の実装上の要点:

- 対象の特定にはオーバーレイのヒットテストが使えない（全画面を覆っているため常に自分が当たる）。`SCShareableContent.windows` をクリック座標で自前に走査する
- 候補から除外するもの: 壁紙・メニューバー・Dock・通知センター等のシステム UI（バンドル ID の列挙と `windowLayer != 0` の 2 段構え）、自アプリのウィンドウ、`isOnScreen == false`、辺が 8pt 未満の不可視ウィンドウ、**他のウィンドウに覆われて見えていないもの**
- **重なり順は `CGWindowListCopyWindowInfo` から取る。`SCShareableContent.windows` の並び順は重なり順ではない**（かつて「実測で完全一致」と記載していたが、macOS 26 での再実測で否定された。詳細と実測値は実装計画 6.11）。`windowID` で両者を対応づけて並べ替え、「クリック点を含む最初のもの」を採る
- **`isOnScreen` は可視判定にならない。** これは「Space 上に配置されている」の意味で、他のウィンドウの背後に完全に隠れていても `true` を返す。重なりは別途自前で計算する（走査線方式で覆われていない領域を矩形群として求め、可視面積が 2% 以下なら候補から外す）
- **自アプリの結果ウィンドウは「候補ではないが遮蔽物」**として扱う。撮影対象にはしないが他アプリのウィンドウを実際に隠しているため、数えないとその陰にいるウィンドウを選べてしまう
- キャプチャには `SCContentFilter(desktopIndependentWindow:)` を使う。対象ウィンドウだけを切り出すため、背後のウィンドウや壁紙は写らず、**手前に重なったウィンドウも写り込まない**（`sourceRect` 方式ではこれが防げない）
- **影は ScreenCaptureKit に任せず自前で合成する。** `ignoreShadowsSingleWindow = false` にすれば影付きで撮れるが、撮影範囲がウィンドウ枠より外に広がるのに `SCContentFilter.contentRect` は影を含まない範囲（`SCWindow.frame` と同一）を返す。実際の撮影範囲が分からないままサイズを指定するため内容が縮小され、目に見えてぼやける（**実測: 鮮明度 7.684 → 4.625**。過去にぼやけを踏んだ 5.132 より更に悪い）。影を除外して等倍で撮り、`ShadowCompositor` で合成することで**ウィンドウ本体はピクセル単位で無劣化**になる（検証済み: 最大差 0）
- `config.width` / `height` は省略できない。省略すると既定サイズ（1920×1080）へ強制されてぼやける。指定した値に内容が合わせ込まれるため、実際の撮影範囲と一致させる必要がある
- 影の形は**画像自身のアルファから作る**。ScreenCaptureKit が返す画像は矩形だが、ウィンドウの角丸は**アルファとして正しく入っている**（実測: 半径 15px の輪郭がアルファに現れる）。`CGContext.setShadow` は描いたものの形に影を落とすので、画像をそのまま描けば角丸に沿った正確な影になる。角丸半径をハードコードして矩形を塗ると、半径が実際とずれた分だけ角に三角形が残る（半径はアプリや macOS のバージョンで変わるため推測してはいけない）
- 画像は**2 回描く**。1 回目は影を出すため、2 回目は影なしで上書きするため（半透明なウィンドウで、下に敷かれた影が透けて中身が暗く見えるのを防ぐ）

> **CPY-04 の既定を変更した理由（実装後の実使用に基づく）**
>
> 当初は「1 アクションで完結させる」ことを重視して既定を「閉じる」としたが、実際に使うと自動で閉じられる方が邪魔だった。

> - 画像とテキストの**両方**をコピーしたい場合、1 回目のコピーで閉じられると成立しない
> - コピーした内容を見返して確認できない
> - 誤認識を直してコピーした直後に、直した結果を確認できない
>
> ウィンドウを閉じるのはユーザーの明示的な操作（「閉じる」ボタン / `Esc`）に任せる。設定項目自体は残すので、閉じる挙動が好みなら有効にできる。

## 6. OCR 精度の実測結果と方針

本仕様は、実装前に Vision.framework の日本語精度を**実測した結果**に基づく。検証コードは AISandbox の `ScreenOCR/ocr.swift` にある。

### 6.1 実測データ

正解テキストを既知の状態で PNG にレンダリングし、文字単位の一致率を測定した（macOS 26 / Swift 6.3）。

| ケース | 1x | 2x | 言語補正 off の効果 |
|---|---|---|---|
| 日本語の文章（ヒラギノ 28pt） | 99.5% | **100%** | 変化なし |
| 小さい文字（ヒラギノ 11pt） | **100%** | 100% | 変化なし |
| コード（Menlo 24pt） | 89.2% | 90.2% | ほぼ変化なし |
| 記号・似た漢字（ヒラギノ 26pt） | 90.2% | 90.2% | 1x で +3.2% |

判明した重要な点:

- **小さい文字は弱点ではない。** 11pt でも 1x で 100%。事前の想定と異なり、拡大前処理は不要である
- **Retina 解像度は必須ではない。** 1x と 2x の差はわずか。ただし取得できるなら高解像度のまま扱う（CAP-02）
- **弱点はコードと記号に集中している**（次項）

### 6.2 誤認識の傾向

コードの実測例:

```
正解: if (l == 1 && O != 0) { return; }
結果: if （1 == 1 88 0 ！= 0） t return；}
```

誤認識は次の 3 種類に分類できる。

1. **全角化**: `(` → `（`、`}` → `｝`、`;` → `；`、`!` → `！`、`~` → `～`、`-` → `ー`
   - Vision が「日本語の文脈」と判断して記号を全角に寄せる。**機械的な変換で復元可能**
2. **字形の混同**: `l`（小文字 L）→ `1`、`O` → `0`、`&&` → `88`、`{` → `t`、`.` → `-`
   - 等幅フォントで特に発生。日本語を候補から外すことで改善が見込める
3. **漢字の細部**: `巳` → `日`、`烏` → `鳥`
   - 原理的に避けにくい。ユーザーが結果ウィンドウで直せる設計（4.3）で補う

日本語の文章については **後処理なしで 99.5〜100%** であり、実用上問題ない。

### 6.3 認識モードの設計

上記を踏まえ、**2 つの認識モード**を用意する。

| モード | 認識言語 | 言語補正 | 後処理 | 用途 |
|---|---|---|---|---|
| **日本語**（既定） | `["ja-JP", "en-US"]` | on | なし | 文章、UI テキスト、ドキュメント |
| **コード** | `["en-US"]` | **off** | 全角 → 半角の正規化 | ソースコード、ID、パス、エラーメッセージ |

要求事項:

- モードは**結果ウィンドウ内で切り替えられ、切り替えると即座に再認識**される（撮り直しを不要にする）
- 直前に使ったモードを次回の既定として記憶する
- コードモードの正規化対象は、少なくとも実測で確認された以下を含む
  - 括弧類: `（）「」［］｛｝` → `()[]{}`
  - 記号: `；：！＝＋－＊／＜＞＆｜％＃＠．，` → 対応する半角
  - 波ダッシュ・長音: `～` `ー` → `~` `-`（コードモードのみ）
    - **実装時に条件を追加**: 長音記号 `ー` を無条件に変換すると日本語を壊す（`サーバーエラー` → `サ-バ-エラ-`）。コードのスクリーンショットには日本語コメントや文字列リテラルが頻繁に含まれるため、**前後に日本語（ひらがな・カタカナ・漢字）がある場合はそのまま残す**。読点 `、`・句点 `。` も同様に扱う
  - 全角空白 → 半角空白
- 字形の混同（`l`/`1` 等）は**自動補正しない**。文脈がないと誤り方が判断できず、正しい文字を壊す危険があるため。ユーザーが結果ウィンドウで直す前提とする

> ~~注: `["en-US"]` 単独指定で `l`/`1` の混同が実際に改善するかは未検証である。~~
>
> **検証済み（実装段階 5）**: `["en-US"]` 単独 + 言語補正 off で **97.0%**、日本語モードでは 69.7%。**差は 27.3 ポイント**で大きく改善する。`l` が `1` に化けず、`&&` も `88` にならず、括弧・セミコロンも全角化しない。残る誤りは `O` → `0` のみ（方針どおり自動補正しない）。詳細は [実装計画.md](実装計画.md) の 4.2 を参照。

## 7. 権限とプライバシー

- **画面収録権限が必須**。macOS 26 では ScreenCaptureKit の利用にユーザー許可が必要である
  - 初回のキャプチャ試行時に OS の許可ダイアログが出る
  - 権限が無い場合は、**システム設定の該当画面へ誘導する案内**を表示する（黙って何も起きない状態にしない）
- OCR は Vision のオンデバイス処理であり、**画像・テキストを外部に送信しない**
- キャプチャ画像を**アプリが自動で永続保存しない**。保存はユーザーが「保存」を押した場合のみ（SAV-01）
- 認識結果の履歴も第 1 版では保持しない（[11](#11-対象外将来課題) の将来課題）

## 8. 非機能要求

| 項目 | 要求 |
|---|---|
| 起動の速さ | メニューバークリックから範囲選択モードに入るまで 200ms 以内を目標とする |
| OCR の速さ | ~~一般的な範囲（1000×600 程度）で 1 秒以内を目標とする~~ → **実測により見直し**。所要時間は画像サイズではなく**行数**でほぼ決まる（4 行 0.76 秒 / 18 行 2.59 秒）。1 秒以内は約 5 行までで、それを超えると超過する。言語補正を切れば速くなるが精度が落ちるため採用しない（[実装計画.md](実装計画.md) 6.10 を参照）。画像プレビューは OCR を待たず先に出るため、体感への影響は小さい |
| メモリ | 常駐時のフットプリントを小さく保つ。キャプチャ画像は結果ウィンドウを閉じたら解放する |
| 応答性 | OCR 実行でメイン UI をブロックしない（画像プレビューを先に出す。4.3） |
| 常駐 | Dock に出さない（`LSUIElement = true`） |

## 10. 受け入れ基準

第 1 版が完成したと判断する条件。

1. メニューバーアイコンのクリックでレティクルが出て、範囲をドラッグ選択できる
2. `Esc` でキャンセルでき、何も起きない
2-a. 選択モード中にウィンドウの上へカーソルを乗せると、**見えている部分だけが**ハイライトされアプリ名とウィンドウタイトルが表示される。クリックするとそのウィンドウがキャプチャされる（CAP-06）
2-b. 影を付ける設定がオンのとき、ウィンドウキャプチャの画像にドロップシャドウが入る。オフのとき枠でぴったり切り取られる（CAP-07）
2-c. デスクトップの何もない場所をクリックすると、何も起きずキャンセルされる
2-d. ウィンドウが他のウィンドウに一部隠れている状態でも、隠れていない完全な状態でキャプチャされる
2-e. 影を付けた場合でも、ウィンドウ本体の文字がぼやけない（等倍で鮮明なまま）
2-f. 他のウィンドウに完全に覆われたウィンドウは、ハイライトもキャプチャもされない
3. キャプチャ後、結果ウィンドウに画像が表示され、「テキストを認識」を押すと下に OCR テキストが表示される
3-a. 結果ウィンドウの「新規キャプチャ」で結果ウィンドウが隠れて選択モードに入り、`Esc` で元の結果ウィンドウが戻る
3-b. ⌘Q・メニューの「終了」で確認が出て、「キャンセル」なら終了しない
4. 日本語の文章のスクリーンショットで、OCR テキストが**目視で読める品質**である（実測 99.5% 以上の水準）
5. 「画像をコピー」の後、他アプリ（プレビュー、メモ等）に画像を貼り付けられる
6. 「テキストをコピー」の後、他アプリにテキストを貼り付けられる
7. 「保存」でデスクトップに、選んだ形式（HEIC / PNG / JPG）のファイルが生成され、Finder で開ける
8. 認識モードをコードに切り替えると、全角記号が半角に正規化される
9. マルチディスプレイ環境で、どちらの画面でもキャプチャできる
10. 画面収録権限が無い状態で、案内が表示される（無反応にならない）
11. 矢印・線・四角・円・テキスト・ぼかし・モザイクを描け、クリックで選び直して動かせる（ANN-01・02）
12. 注釈を描いて「画像をコピー」すると、貼り付けた画像に注釈が入っている。OCR の結果は注釈の影響を受けない（ANN-04・06）
13. OCR テキスト欄で ⌘Z・文字入力・`Esc` が従来どおり動く。キャンバスで `Esc` を押すと、選択があれば選択解除、なければウィンドウが閉じる（ANN-12）
14. HDR 対応ディスプレイで HDR を選ぶと明部が光り、SDR を選ぶと光らない。HDR の HEIC・JPG を保存してプレビューで開くと HDR で表示される。HDR でコピーした画像を X に貼れる（HDR-02〜06）

## 11. 対象外・将来課題

第 1 版では実装しないが、設計上の余地を残しておくもの。

- **グローバルホットキー**: メニューバークリックを介さずキーボードだけで起動する。常用するなら次に欲しくなる機能
- **認識履歴の蓄積と検索**: 認識結果をためて後から探せるようにする（「あのエラーメッセージどこで見たか」の解決）。プライバシー方針（7）と併せて設計が必要
- **認識テキストの種類による分岐**: URL なら開く、コードならエディタへ、英文なら翻訳。既存の `SnapAsk`（選択テキスト → Gemini）と発想が重なる
- **LLM を用いた構造化**: 表を Markdown に変換する、手書きを整える等。オンデバイス完結の原則（7）を破るため、採用するなら明示的な選択制にする
- ~~**ウィンドウ単位・全画面のキャプチャ**: 現状は範囲選択のみ~~ → **ウィンドウ単位は実装済み**（CAP-06 / CAP-07）。全画面のキャプチャは未対応
- **閉じた後の注釈の再編集**: 現状は結果ウィンドウを開いている間だけ編集できる。PNG のメタデータへの編集情報の埋め込み、専用の書類形式（`.jpscreenshot` など）は未対応。データ構造は埋め込みへ移れる形（`Sendable` な値型）にしてある
- **注釈の細部**: テキストの座布団（背景）、ぼかし範囲を OCR から除外すること、キャンバスでの `⌘C`（オブジェクトのコピー）は対象外
- **縦書きの認識**: Vision は認識するが順序が壊れることがある。未検証
- **定期キャプチャによる画面変化の監視**: OCR を「取得」ではなく「観測」に使う用途
